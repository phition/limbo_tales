## 1. 요약

림보 테일즈는 **"어두운 방(A Dark Room)식 영지 경영 + 다키스트 던전식 하드코어 파티 던전 + 비동기 PvP/레이드/침공/진영전"** 을 하나의 모바일 앱에 담은 다크 판타지 RPG입니다. v1.1.x에서는 **정식 출시 체계**(Google Play Games 업적·리더보드, 강제 업데이트, 실광고 ID, PC/태블릿 반응형)가 갖춰졌고, UI는 "다크 고딕 & 앤티크 골드" 테마로 전면 개편됐습니다.

| 구분 | 판단 |
| :--- | :--- |
| 게임 디자인 | 루프가 탄탄하고 콘텐츠 볼륨이 충분함. 다만 성장 축과 모드가 계속 늘어 신규 유저가 받는 부담이 커지고 있음 |
| 출시 준비도 | 클라이언트 쪽 출시 인프라는 갖춰짐. **서버 보안은 출시가 불가능한 수준** |
| 코드 건강도 | 이전보다 나빠짐. 타입 오류 0건 → **178건**. 확인된 런타임 버그 2건 |
| 최우선 과제 | ① Firebase 규칙 잠금 ② 타입 오류·런타임 버그 정리 ③ 진영전의 서버화 여부 결정 |

## 3. 핵심 루프

```
 ┌─────────── 영지(방주 성채) ───────────┐        ┌──────── 심연(던전) ────────┐
 │ 성화 점화 → 시설 13종 증축·유지비     │ 보급 → │ 위험도·횃불·식량·배낭 관리 │
 │ 주점 고용 · 전직 · 초월 각성          │        │ 층별 MUD 이벤트(직업 분기) │
 │ 병기창 단조·강화·인챈트·정화          │ ← 귀환 │ 3인 턴제 전투 · 광폭화 보스│
 │ 묘지(전사자 → 영구 가호)              │  전멸→ │ 영구 사망                  │
 └───────────────┬───────────────────────┘        └────────────────────────────┘
                 │ 차원 게이트
     ┌───────────┴─────────────────────────────────────────────────────┐
     │ 3v3 아레나(ELO) · 네메시스 3부위 레이드 · 영지 침공(30% 약탈)   │
     │ · 진영전(3진영 거점 점령, 시즌제)  → 명예 주화 · 신화 장비      │
     └─────────────────────────────────────────────────────────────────┘
```

영지는 던전을 위한 보급·성장 기지이고, 던전은 영지를 위한 재료 공급원입니다. 엔드게임은 둘 다에 보상을 돌려줍니다. 세 축이 서로 의존하는 구조가 명확하며, 장르 레퍼런스에서 핵심 재미 요소만 골라 잘 연결했습니다.

## 4. 시스템별 분석

### 4.1 영지 — 볼거리는 크게 좋아졌지만, 화면 깊이가 깊어짐

**v1.1.x 변화**
- 지하 광장 디오라마 배경 + 성화 점화 시 10초 시네마틱 루프(꺼지면 흑백, 켜지면 컬러 전환).
- 3D 세로 휠 시설 내비게이터, 시설 워크스테이션 드로어, 미해금 시설 잠금 표시.
- 오프라인 정산은 1시간 이상 미접속 시에만 표시. 골드 상한 30만(상업 네트워크 활성화 시 50만).
- 영지 식량과 던전 식량을 분리하고, 6층 이상에서 "던전 도시락" 드롭.

**평가**
- "꺼진 성채가 불을 붙이면 살아난다"는 연출은 어두운 방 계열의 감성을 시각적으로 잘 옮겼습니다. 첫 세션 경험에 큰 플러스입니다.
- 반면 **허브 → 휠 → 드로어 → 모달**로 진입 단계가 깊어졌습니다. 자주 쓰는 행동(건설, 고용, 출정)은 빠른 시설 도크(`QuickFacilityDock`)처럼 **2탭 안에 끝나도록** 유지하는 것이 좋습니다.
- 시설 13종 × 유지비 × 다중 자원 구조에서 "다음에 무엇을 지을지"를 알려주는 추천 장치가 여전히 약합니다. 튜토리얼이 생산 시설까지 안내하도록 보강됐지만, 중반(Lv.4~6 유지비 개시 구간) 안내도 필요합니다.

### 4.2 던전 — 게임의 정체성이 가장 잘 드러나는 곳

- 직업 구성에 따라 선택지가 달라지는 층별 MUD 이벤트(30개), 광폭화 보스 선택, 영구 사망 → 묘지 가호 구조는 이 게임만의 강점입니다.
- 11층 무간도는 몬스터 Lv.40~499, 위험도 350/700에서 중간 보스, 중간 보스 처치 시 HP/MP 50% 회복으로 정리되어 "끝없는 하강" 엔드게임의 형태를 갖췄습니다.
- 보급 체계 개편(던전 내 비상 식량 드롭)으로 초반 보급 스트레스가 줄었습니다.

**제언**: 층별 이벤트는 마케팅 소재(스토어 스크린샷, 플레이어블 광고)로 더 적극적으로 쓸 만합니다. 저장소에 이미 5층 플레이어블 광고 빌드가 있으니, 전투 장면뿐 아니라 "직업에 따라 바뀌는 선택지"도 넣으면 차별점이 잘 전달됩니다.

### 4.3 전투 — 깊이는 충분, 공식 일원화는 절반 정도 진행

- 상태이상 폭발 콤보, 피버 게이지, 무기 6계열 특성, 에픽 공용 접미사 인챈트 6종(흡혈·집중·관통·저항 등)이 추가됐습니다.
- **개선**: 침공전이 PvE와 같은 DR 공식(`DR / (def + DR)`, 10층 K=500)과 치명타·회피 판정으로 맞춰졌습니다.
- **남은 문제**: 공식이 여전히 화면 컴포넌트마다 따로 구현돼 있습니다.

| 모드 | 방어 감쇄 구현 위치 |
| :--- | :--- |
| 던전 | `BattleScreen.tsx` (층별 K) + 일부 추정치는 `100/(100+def)` (7648행) |
| 아레나 | `ArenaScreen.tsx` — `1 − def/(def + getArenaDRConstant())`(2248행)와 `100/(100 + def × ARENA_DEF_SCALE)`(2287행)를 **한 파일 안에서 혼용** |
| 침공 | `InvasionBattleScreen.tsx` — `invasionDR / (def + invasionDR)` |
| 네메시스 | `NemesisView.tsx` — `K/(def+K)`, 장비 발동·지원 공격은 500 상수 하드코딩 |

같은 영웅·같은 장비라도 모드마다 결과가 미세하게 달라질 수 있습니다. 밸런스 패치 때마다 4개 파일을 함께 수정해야 하는 구조입니다.

### 4.4 성장 — 축이 너무 많음

전직(10/30/60레벨) · 초월 각성 · 등급(N~L) · 단조 · 강화 · 인챈트(접두/접미/순수/에픽) · 정화 · 마도서 연독/강화/제작 · 시너지 · 유대 · 묘지 가호 · 심연 촉매 · 4인 편성(리더/오퍼레이터). 하드코어 층에게는 장점이지만, 중반 이탈의 가장 큰 원인이 될 수 있습니다. 축별 **해금 시점을 분산**하고, 처음 해금될 때 한 장짜리 안내를 띄우는 것을 권장합니다.

> 남아 있는 불편: 습득 스킬 6칸이 가득 찬 상태에서 마도서를 읽으면 연독률이 99%에서 멈추지만 **마도서는 그대로 소모**됩니다(`GameManager.ts` 5321행 부근). 소모를 막고 망각/교체 선택 창을 띄우는 것이 맞습니다.

### 4.5 엔드게임과 신규 진영전

**아레나·네메시스·침공**은 편성 UI(4인, 리더 금빛 프레임), 대상 7명 매칭, 배속 전환, 반응형 VFX까지 다듬어졌습니다. 네메시스는 상태이상 저항 90%·틱 피해 10% 상한으로 "DoT 조합 하나로 다 녹이는" 메타를 막았습니다.

**진영전(Faction War, `FactionWarView.tsx` + `data/factionWar.ts`)** — 11/18 추가
- 3진영(창백한 여명회 / 심연 마도 학회 / 강철 방주 연맹), 본진 3 + 내곽·접경 거점 6 + 중앙 아카식 코어로 이루어진 성좌형 지도. 관문 돌파 → 교두보 → 거점 점령 → 코어 패권으로 이어지는 구조.
- 시즌·주차, 수비대 주둔(피로도 스택), 공성 토큰, 성좌 인장 상점까지 설계가 촘촘합니다.

**하지만 현재는 사실상 혼자 하는 시뮬레이션입니다.**
- 상태 전체가 `localStorage`(`limbo_faction_war_state_v1`)에만 저장되고, Firebase 동기화가 없습니다.
- 초기값이 테스트용으로 고정돼 있습니다: `currentWeek: 2`, `seasonDay: 8`, `playerFaction: 'dawn'`, 인장 1,500, 진영 점수 1250/1180/1210.
- **"수비대 주둔" 버튼이 호출하는 `handleDeployGarrison` 함수가 존재하지 않습니다**(1106·1545행). 누르면 ReferenceError가 나고 아무 일도 일어나지 않습니다.

→ 출시 전에 **"서버 기반 진짜 진영전으로 만들지, 싱글 콘텐츠로 이름과 설명을 바꿀지"** 결정해야 합니다. 서버화한다면 점령·점수·시즌 정산은 반드시 Cloud Functions에서 처리해야 합니다(6.1 참고).

### 4.6 수익화

- AdMob 실광고 ID와 테스트 ID 전환 스위치가 구현돼 있습니다. 보상형 광고 중심이고, "전멸 부활 광고는 배제"한 원칙은 장르에 맞는 좋은 판단입니다.
- Google Ads용 HTML5 플레이어블 광고(5층, Lv.20 에픽 파티) 빌드 스크립트가 있습니다.
- 인앱 결제(IAP)는 여전히 없습니다. 하드코어 RPG 층을 고려하면 **광고 제거 + 편의(배낭/보급 프리셋) 패스 1종**만으로도 ARPU 상한이 크게 오를 것입니다.

### 4.7 아트·사운드·현지화

- 다크 고딕 & 앤티크 골드 테마로 통일됐고, 시설 배너·초상화·시네마틱 영상이 추가됐습니다.
- 사운드는 여전히 Web Audio 실시간 합성이라 용량 부담이 없습니다.
- 현지화는 사전 + 패턴 기반 런타임 치환 방식입니다. `translationDictionary.ts`에 **중복 키가 114개** 있어(TS1117), 같은 한국어 문장에 대해 뒤에 정의된 번역이 앞의 것을 조용히 덮어씁니다. 의도하지 않은 번역이 나올 수 있습니다.

## 5. 강점

1. **장르 조합의 선명함**: 방치형 영지 + 하드코어 던전 + 비동기 경쟁 콘텐츠의 조합은 모바일에서 장기 리텐션이 검증된 축들입니다.
2. **영구 사망을 성장으로 바꾸는 장치**(묘지, 선조의 가호)와 **직업 반응형 MUD 이벤트**가 뚜렷한 정체성을 만듭니다.
3. **출시 인프라**: Play Games 업적·리더보드, 강제 업데이트(`AppVersionService`), 실광고, PC/태블릿 반응형, Android CI 빌드까지 갖췄습니다.
4. **연출 품질 향상**: 성화 시네마틱, 디오라마, 통일된 테마로 첫인상이 크게 좋아졌습니다.
5. **코드 분할 진척**: 스튜디오 모달·`GameManager` 등이 별도 청크로 분리됐고, 모바일 빌드에서는 관리 도구를 제외합니다.

## 6. 리스크 (우선순위 순)

### 6.1 [P0] Firebase 규칙이 사실상 전부 열려 있음 — 이전보다 범위가 커짐

`database.rules.json`에서 아래 경로가 **인증 없이 누구나 쓰기 가능**합니다.

| 경로 | 악용 시 영향 |
| :--- | :--- |
| `users/$uid/progress`, `profile` (+ `users` 전체 읽기) | 아무 유저의 세이브를 읽기·덮어쓰기·삭제 가능 |
| `app_version` | `forceUpdate: true`를 쓰면 **전 유저가 강제 업데이트 화면에 갇힘**(사실상 서비스 중단) |
| `system_config`, `game_data`, `encyclopedia_data`, `arena_edict` | 전역 밸런스·설정을 마음대로 변조 가능 |
| `arena_leaderboard`, `world_boss` | 랭킹·레이드 보스 HP 조작 가능 |
| `callsigns`, `recent_active_users`, `system_stats`, `dungeon_recent_visits` | 닉네임 선점·통계 오염 |

`firestore.rules`도 게시판을 뺀 모든 문서에 `allow read, write: if true`가 걸려 있습니다.

추가로 관련된 점:
- **관리자(마스터) 판정이 클라이언트에만 있습니다**(`FirebaseService.isMasterUser()` — 특정 UID/이메일 비교). 화면을 숨길 뿐 DB 쓰기를 막지 못합니다.
- `commander_attack_notices` 경로는 규칙에 없어서 RTDB 기본값(거부)에 걸립니다. 그런데 코드가 오류를 `catch(() => {})`로 삼키고 있어서, **침공 알림이 조용히 실패하고 있을 가능성이 큽니다.**
- Google 번역 API 키가 `VITE_` 환경변수로 클라이언트 번들에 들어갑니다. Google Cloud 콘솔에서 HTTP 리퍼러/Android 앱 제한과 사용량 상한을 반드시 걸어 두세요.

**즉시 조치(1~2일)**
1. `users/$uid` 쓰기: `auth != null && auth.uid === $uid`. `users` 루트 전체 읽기 제거.
2. `app_version`, `system_config`, `game_data`, `encyclopedia_data`, `arena_edict`: 쓰기를 관리자 UID(또는 custom claim)로만 제한.
3. Firestore 전체 허용 규칙 삭제.
4. `commander_attack_notices` 규칙 추가(대상 유저만 읽기, 인증 유저만 push).

**단기**: 랭킹·레이드 누적 피해·침공 약탈·진영전 점수는 Cloud Functions에서 검증해 기록합니다.

## 8. 결론

v1.1.5의 림보 테일즈는 **게임으로서는 출시할 만한 단계**에 와 있습니다. 루프가 맞물려 돌아가고, 정체성이 분명하며, 연출과 출시 인프라도 갖췄습니다.

다만 **서비스로서는 아직 출시할 수 없는 단계**입니다. 누구나 다른 유저의 세이브를 지우거나 전 유저를 강제 업데이트 화면에 가둘 수 있는 상태에서는, 경쟁 콘텐츠(아레나·침공·진영전)를 늘릴수록 위험도 함께 커집니다.

새 모드를 더하기 전에 **방어(Firebase 규칙) → 수리(타입 오류·버그) → 결정(진영전의 성격)** 순서로 정리하는 것을 권장합니다. 이것만 끝나도 지금까지 쌓은 볼륨이 그대로 경쟁력이 됩니다.
